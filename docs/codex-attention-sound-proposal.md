# Codex 部分失败 attention / notice 音效（提案）

本文件只做声音设计。不生成音频，不修改生产代码，不接入 `playDing`，不打开默认声音开关，不把声音接到 `completed_signal` 或其他 Agent。

每条结论标注：

- **已验证事实**：真实联调、已落地实现或测试已经证明。
- **产品设计建议**：本轮提出的声音方案，尚未制作资源，也尚未实播。

`shouldNotify` 必须继续为 `false`。`completed_signal` 不是任务成功。部分失败不是整轮失败。

---

## 1. 设计目标

声音只表达一件事：

> 请注意查看结果。

不表达：

- 任务已成功
- 任务全部完成
- 整轮失败
- 用户必须立即处理

它是气泡的附属提示，不是独立通知渠道。没有气泡，就没有声音。

是否真的有必要：

- **产品设计建议**：不是正确性必需。姿态 `attention` 和气泡文案已经能说明「这一轮结束了，但有工具失败」。声音只服务「用户当时没看屏幕」这一种情况。
- 因此默认应关闭；没有独立音效资源前必须保持静音。
- 若以后制作资源，它仍应比完成音更轻、更短、更少出现。

---

## 2. 适用状态

唯一允许的 candidate：

```text
completed_with_partial_failure
```

还必须同时满足（**已验证事实**：策略层已按此判定）：

1. 该 session/turn 的部分失败气泡已经真正发送到渲染进程
2. `acknowledgePresented` 已完成
3. `bubblePending` 不是 `true`
4. `codexCandidateSoundEnabled=true`（当前默认 false）
5. 该 session/turn 尚未占用过声音去重键
6. 不是 priming / history
7. 不是 stale / unknown
8. 仓库里存在独立 attention 音（当前 `CODEX_ATTENTION_SOUND_AVAILABLE=false`，因此即便前 7 条满足，`playSound` 仍为 false）

产品含义对应气泡文案（**已验证事实**）：

```text
这一轮结束了，但有工具失败，请查看结果。
```

---

## 3. 禁止状态

以下状态本轮和下一阶段都不得播放这条音：

| 状态 | 原因 |
|---|---|
| `working` | 只是干活，不应出声 |
| `completed_signal` | 协议结束，不是成功，更不是部分失败 |
| `unknown` / `observation_stale` | 观察不可靠，不得用声音补完语义 |
| `cancelled` | 未作为用户提醒接入 |
| `failed` | 未作为用户提醒接入；且容易被听成整轮失败警报 |
| `incomplete` | 未作为用户提醒接入 |
| `waiting` | 未作为用户提醒接入 |
| 进行中的 `tool_failed`（尚未形成 `completed_with_partial_failure`） | 工具还在跑，不应提前出声 |
| 旧 Codex `done` | 已中性化，不得恢复完成音 |
| Claude / Cursor / Grok 完成事件 | 其他 Agent 继续走自己的完成音开关 |

也不得：

- 复用 `playDing`
- 把 `BubblePayload.sound=true` 接到现有完成音路径
- 通过声音暗示成功、全部完成、整轮失败或必须立刻处理

## 4. 音效设计建议

对照现有完成音（**已验证事实**）：

`playDing` 是 WebAudio 合成的两音「叮咚」：C6（1046.5 Hz）→ E6（1318.5 Hz），间隔 120ms，正弦波，峰值增益约 0.15，听感偏愉悦、完成、庆祝。

部分失败音必须和它听起来不像一家人。

### 推荐类型

**产品设计建议：单音、极短、中性 notice。**

- 一个短促的软点击 / 轻叩，不是旋律
- 波形：sine 或很轻的 triangle；不要 saw / square（容易尖、容易像警报）
- 音高：低于完成音。建议 A5（880 Hz）或 G5（784 Hz），不要走 C6→E6 大三度上行
- 包络：快起、更快收，不要第二下
- 不要下行小二度、不要重复敲击、不要低频蜂鸣

听感目标：像有人用指节在桌面上轻敲一下。  
不是门铃，不是错误蜂鸣，不是系统警报。

### 不推荐的类型

| 方案 | 风险 |
|---|---|
| 复用 `playDing` | 用户会听成「任务完成」。已明确禁止 |
| 把 `playDing` 降调或少放一个音 | 仍是同一套完成音色，容易混淆 |
| 双音下行 | 容易听成「失败 / 取消」 |
| 低音蜂鸣、连续两三次 | 警报感 |
| macOS 系统错误音 / 通知中心 | 像必须立刻处理，而且跨应用抢注意力 |
| 现场再写一个全局合成器并和 `playDing` 共用入口 | 以后很容易再次接错 |

## 5. 音量和时长建议

**产品设计建议：**

| 项 | 建议 | 理由 |
|---|---|---|
| 时长 | 80–160ms，上限 200ms | 比 `playDing` 的约 360ms 两音结构更短 |
| 响度 | 明显低于完成音；若用 WebAudio，峰值增益约 0.06–0.09 | `playDing` 峰值约 0.15，notice 应大约减半 |
| 声道 | 单声道即可 | 信息量不需要立体声 |
| 系统音量 | 跟随用户系统音量，不再单独抬高 | 不要做成系统级通知 |

不需要震动、不需要 Dock 弹跳、不需要通知中心横幅。`shouldNotify` 保持 false。

---

## 6. 气泡与声音的绑定

**已验证事实：** 策略层已经要求声音接收「气泡已实际展示」的结果，而不是只看 candidate。

必须保持：

| 情况 | 是否播放 |
|---|---|
| 气泡真正发送成功，且已 `acknowledgePresented` | 才允许进入声音判定 |
| 气泡被去重抑制 | 不播放 |
| 气泡还在排队（另有 session `working`） | 不播放 |
| `bubblePending=true` | 不播放 |
| 窗口隐藏，`sendBubble` 未发出 | 不播放 |
| priming / history | 不播放 |
| 重复 observation / 同一 candidate 再扫一次 | 不播放 |

声音不能独立于气泡触发。用户没看到这条提醒，就不该先听到声音。

窗口隐藏 = 用户明确不想被打扰。隐藏时不弹气泡，也就不播放声音。

---

## 7. 多 session 规则

沿用现有视觉和气泡仲裁（**已验证事实**）：

- A 部分失败、B 仍在 `working`：A 的气泡入队；A 未真正展示前不出声；B 的 working 不出声
- A 已展示并已获得一次声音资格后，B `completed_signal`：B 不出声、不播完成音
- A 已展示、B 又开始 `working`：不因 B working 再出声
- 不同 session 隔离；同一 session 的新 turn 可用新 key 再获得一次资格
- 旧 turn 的声音状态不得覆盖新 turn
- 多个未展示的部分失败：每个 session/turn 最多一条气泡、一次声音；不得串线

不因为「同时有两个失败」就连播两声。若两个气泡在同一轮释放，也只按现有气泡策略弹一次通用文案；声音跟随那一次真实展示，而不是按失败 session 计数连击。

---

## 8. 去重规则

**已验证事实：** 声音去重键已经是：

```text
fileAlias|sessionId + turn:<官方 turnId> 或 bound:<本地 boundary> + candidate + presented
```

不使用当前时间戳伪造 turn。

**产品设计建议：**

- 同一 session/turn、同一 `completed_with_partial_failure`：最多一次声音资格
- 新官方 `turnId`，或本地 boundary 因新 turn working 递增：允许再获得一次
- 额外全局冷却不是必需。现有气泡本身每个 turn 最多一条，声音绑在那一条上已经够用
- 若以后出现「同 tick 释放多条队列」的实现变化，再加 1.5–2 秒全局冷却，避免连击。当前不要先做

---

## 9. 默认开关策略

回答设置相关问题：

| 问题 | 建议 | 性质 |
|---|---|---|
| 是否允许用户关闭 | 以后允许，用已有字段 `codexCandidateSoundEnabled` | 产品设计建议 |
| 默认是否关闭 | 是，必须 `false` | 已验证事实（defaults） |
| 现在要不要设置页入口 | 不要 | 已验证事实（设置页不展示）；也是产品设计建议（资源未稳之前继续隐藏） |
| 是否需要系统声音级别 | 不需要 | 产品设计建议 |
| 是否需要独立静音设置 | 先复用 `codexCandidateSoundEnabled`，不要再加第三套静音 | 产品设计建议 |
| 没有资源时怎么办 | 保持 `playSound=false`，`CODEX_ATTENTION_SOUND_AVAILABLE=false` | 已验证事实 |

露出开关的前提：

1. 独立 attention 音已经能实播
2. 和 `playDing` 听感可区分
3. 只跟真实展示的部分失败气泡
4. 默认仍然关闭
5. 文案写清「不是完成音，也不是失败警报」

在此之前让用户看到一个打开后没声音的开关，会造成「坏了」的误判。设置页联调已证明：隐藏声音开关、只暴露视觉和气泡，配置隔离是成立的。

## 10. 失败和静音处理

**产品设计建议 / 已有实现对齐：**

- 没有独立资源：静音，不要退回 `playDing`
- AudioContext 不可用、被浏览器/系统挂起：吞掉异常，不影响气泡和桌宠（完成音已是这个原则）
- 声音播放失败：气泡仍然留下，姿态生命周期不变
- 用户关掉 `codexCandidateSoundEnabled`：不再进入可播路径
- 用户关掉气泡开关：没有真实气泡，声音也不该出现
- 用户隐藏宠物窗口：气泡不发送，声音不发送
- 诊断写入失败：不影响是否出声；出声也不写新的用户通知

不要用声音失败去重试、不要升格 `failed`、不要打开 `shouldNotify`。

---

## 11. 是否建议制作音频文件

**产品设计建议：现在可以开始设计规格，但还不要把文件提交进仓库，更不要先接入。**

制作的前提是产品确认「可选、默认关、只跟气泡」这三条不变。

制作的理由：

- 完成音已经占用了「现场合成两音叮咚」这条路
- 独立文件能避免以后有人把 notice 接到 `playDing`
- 设计师可以单独听、单独改，不必改 `PetView.tsx`

不制作、继续只写策略层也可以。当前用户行为已经正确：静音。

---

## 12. 如果制作，建议的文件格式

**产品设计建议：**

| 项 | 建议 |
|---|---|
| 容器 | `.wav`（PCM）优先；不要 mp3 |
| 采样 | 44.1 kHz 或 48 kHz，16-bit，mono |
| 时长 | 实际可听 80–160ms，文件总长可含 20ms 淡出，整文件 < 250ms |
| 响度 | 峰值明显低于完成音；不要 0 dBFS 满幅 |
| 内容 | 单音软叩，无第二个音高 |
| 命名 | 例如 `codex-partial-failure-notice.wav`，不要叫 ding / success / error / alert |
| 存放 | 将来若接入，单独资源目录；不要改 `playDing` 所在逻辑来「顺便播一下」 |

不建议：

- 现场改 `playDing` 参数冒充 notice
- 引入系统 `NSSound` / 通知音
- 为了「更有存在感」做成 1 秒以上的垫音

WebAudio 另写 `playNotice()` 也可以，但必须与 `playDing` 分函数、分入口、分开关。即便走合成，也不要先做文件。本轮两者都不做。

## 13. 不同方案的风险

| 方案 | 主要风险 | 结论 |
|---|---|---|
| 现在就接入 `playDing` | 把部分失败听成成功 | 禁止 |
| 默认打开声音 | 打扰；资源还不存在时是空开关 | 禁止 |
| 现在就在设置页露出声音开关 | 打开后没声音，用户以为坏了 | 现在不要 |
| 系统通知音 | 「必须立刻处理」；也和 `shouldNotify=false` 冲突 | 不采用 |
| 失败警报音 | 把部分失败听成整轮失败 | 不采用 |
| 每个 working/完成都出声 | 噪声，且破坏已中性化的 `completed_signal` | 禁止 |
| 气泡未展示也出声 | 用户没上下文，只听到一声怪响 | 禁止 |
| 窗口隐藏也出声 | 违反「隐藏 = 别打扰」 | 禁止 |
| 多 session 连播 | 像警报 | 不采用 |
| 先做 wav 再改策略 | 资源和策略可能对不上 | 先冻结策略，再做 1 个短文件试听 |
| 不做声音 | 只靠气泡，部分用户会漏看 | 可接受；默认就应如此 |

## 14. 最终推荐方案

**建议加入 attention 音效，但是可选能力，不是现在就要实播。**

规格：

```text
类型：单音、轻量 notice / 软叩
时长：80–160ms
响度：低于 playDing
音高：G5–A5 一带，禁止 C6→E6 上行叮咚
波形：sine / 轻 triangle
次数：每个 session/turn 最多 1 次
绑定：只在部分失败气泡真正发送成功之后
窗口隐藏：不播放
默认：codexCandidateSoundEnabled=false
设置页：暂时不展示
资源未就绪：playSound 保持 false
禁止复用：playDing
```

触发顺序保持现有实现：

```text
部分失败候选
  → 气泡真正 sendBubble 成功
  → acknowledgePresented
  → 声音策略判定
  → 仅当开关打开且独立资源存在时才实播
```

同 tick 不得为了出声再 `sendPetState(idle)`，以免清掉气泡。这是姿态生命周期的已有约束，声音不得破坏它。

## 15. 哪些是已验证事实

- 仓库没有独立 attention / notice 音，只有 `playDing` 完成音。
- `playDing` 是 C6→E6 两音叮咚，由 `BubblePayload.sound` 触发。
- Codex 旧 `done` 不再播放完成音。
- `completed_signal` 不弹成功气泡、不播完成音。
- 部分失败气泡文案是中性提醒，不是成功也不是整轮失败。
- 声音策略层已经存在，且必须看到「气泡已实际展示」。
- 同一 session/turn 声音去重键已定义，不用时间戳伪造 turn。
- `CODEX_ATTENTION_SOUND_AVAILABLE=false`，因此当前 `playSound` 恒为 false。
- `codexCandidateSoundEnabled` 默认 false，设置页不展示。
- 设置页视觉 / 气泡开关已真实联调：点击、持久化、重启、用户长期配置隔离通过。
- 窗口隐藏时 `sendBubble` 不发送；隐藏时也不应出声。
- priming / history 不进视觉和气泡，声音策略同样排除。
- `shouldNotify` 恒为 false。
- 多 session 下，working 优先于未展示的部分失败；已展示的部分失败不再单独钉住 `attention`。

---

## 16. 哪些是产品设计建议

- 声音有用，但不是必需；默认关着是正确产品状态。
- 采用单音软叩，不用双音，不用警报，不用系统通知。
- 时长 80–160ms，响度低于完成音。
- 不需要额外全局冷却；现有 session/turn 去重足够。
- 不需要系统声音级别，不需要第二套静音开关。
- 等独立资源能实播、和完成音可区分之后，再考虑在设置页露出声音开关。
- 若制作文件，用短的 mono PCM wav，文件名不要带 success / error / ding。
- 制作文件之前不要改 `main.ts`、不要改 `playDing`、不要把 `sound=true` 接到现有气泡路径。
- `failed` / `incomplete` / `cancelled` / `unknown` 即使以后做用户提醒，也不自动共用这条 notice 音；那些状态要另开设计。

## 附录：17 个设计问题的直接回答

1. **是否必要：** 非必需，可选。
2. **音效类型：** 单音轻量 notice / 软叩。
3. **时长：** 80–160ms。
4. **音量：** 低于 `playDing`，跟随系统音量。
5. **单音还是双音：** 单音。禁止完成音式双音。
6. **如何避免和完成音混淆：** 不同音高、单音、更短、更弱；禁止复用 `playDing` 和它的大三度上行。
7. **如何避免失败警报：** 不用低频蜂鸣、不用重复敲击、不用系统错误音、文案也不说「失败必须处理」。
8. **系统声音级别：** 不需要。
9. **静音设置：** 复用 `codexCandidateSoundEnabled`；资源未稳之前不展示。
10. **播放冷却：** 当前不必；去重已按 session/turn。
11. **同一 session/turn 去重：** 现有 `…|candidate|presented` 键，最多一次。
12. **气泡未实际展示：** 不播放。
13. **窗口隐藏：** 不播放。
14. **多 session：** 跟随气泡队列；未展示不出声；不连击。
15. **是否允许用户关闭：** 以后允许，默认就关。
16. **默认是否关闭：** 是。
17. **是否需要设置页入口：** 现在不要。
